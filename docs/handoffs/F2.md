## The `--brand-4` forward-reference (read this before touching CoverGradient/StatTile)

01 §1 defines `--brand-4` and F1 is adding it to `globals.css` in parallel — it doesn't exist in
this worktree yet. `CoverGradient`'s brand ramp and `StatTile`'s `brand-4` accent both reference it
by *name*, per the mission ("write against token names, never redefine a token yourself"). Without
a fallback, `var(--brand-4)` is undefined, which makes the whole `linear-gradient(...)` /
`color: ...` declaration invalid at computed-value time (not just that one stop) — I caught this by
screenshotting the style guide and seeing washed-out grey cards where the gradient should be. Both
components now use `var(--brand-4, var(--brand-3))` so they degrade to a valid, close colour instead
of breaking, and pick up the real value automatically once F1's PR lands — no follow-up needed here.

## `CoverGradient` algorithm

`getCoverGradientStops(seed)` (also exported, for reuse by a future placeholder-image script):

1. Hash `seed` with FNV-1a (`>>> 0` to keep it an unsigned 32-bit int) — pure, and identical on the
   server and in the browser for the same string, so SSR and hydration always agree.
2. `fromIndex = hash % 4` picks a stop from the ramp `['--brand', '--brand-2', '--brand-3',
   '--brand-4']`; `toIndex` is offset from `fromIndex` by 1–3 (derived from the rest of the hash),
   guaranteeing the two stops are always distinct.
3. `hueRotate = (hash % 41) - 20` — a `filter: hue-rotate()` in the range **-20deg to +20deg**, so
   two projects that land on the same stop pair still look distinct, and the result stays inside
   "the brand range" per 02 §4 (never wanders into an unrelated hue).
4. Renders `linear-gradient(135deg, stop1, stop2)` (with the `--brand-4` fallback above) plus an
   absolutely-positioned bottom scrim (`oklch(0 0 0 / 0.55)` → transparent) so an overlaid caption
   stays legible, and an optional monogram (first letters of the first two words of `label ?? seed`,
   28px/600 `white/60`, bottom-left) when `monogram` is set.
5. `role="img"` + `aria-label={label}` when a label is given, `aria-hidden` otherwise (it's always
   decorative — the real caption is rendered by the calling card, not by `CoverGradient` itself).

## Decisions

- **Hit-area technique measures via the `::after` pseudo-element, not the button's own
  `getBoundingClientRect()`.** The spec explicitly asks for "padded with a pseudo-element when the
  visual box is smaller" (02 "Button"), so the *visible* box stays 36/40px while the *painted* hit
  box is 44px. I verified this with an ad hoc Playwright script reading
  `getComputedStyle(el, '::after')`'s inset — `default`/`xs`/`sm`/`icon` all resolve to a 44px+ hit
  box; `lg` needs no pseudo-element because its own box is already 44px. If 3.2 writes an automated
  a11y check for this later, it needs to read the pseudo-element the same way, not
  `button.boundingBox()` — that only sees the visible (smaller) box.
- **Focus ring stays box-shadow-based (`ring-3 ring-ring/50` + `border-ring`), not the native
  `outline`.** This was already 1.1's pattern (`outline-none` + a Tailwind ring), not something I
  introduced. I verified with a keyboard `Tab` (not `.focus()`, which doesn't trigger
  `:focus-visible` in Chromium) that the ring box-shadow actually paints on focus. The global
  `:focus-visible { outline: 2px solid var(--ring) }` in `globals.css` (01 §7) still covers any
  plain element that doesn't have its own primitive-level ring (e.g. the `#` permalink in
  `SectionHeading`).
- **`Input`/`Textarea` own their error message** rather than requiring a separate `FieldError`.
  `FieldError` still exists in `ui/field.tsx` for the multi-error / `errors` array case; for the
  common single-message case, passing `error` to the input is enough to get the border, the message
  and the aria wiring in one place — this is what the unit tests exercise.
- **Illustrative demos for page-specific components stay inline in `styleguide/page.tsx`,** not as
  files under `components/projects|experiments|bio|layout`. Task 8 forbids me from building
  `ProjectCard`/`ExperimentCard`/`TimelineNode`/`FilterChip`/nav — the style guide still needs to
  *show* them per task 6, so I composed them from primitives/shared components I do own, directly in
  the page. U1/U4/U5 should treat these as **reference for visual target only**, not as components to
  import — build your own from `02-component-specs.md`.
- **`--brand-4` / `--warning` / `--ease-brand` / `--dur-ui` / `--dur-reveal`** are referenced by name
  wherever the spec calls for them (button transitions/easing, `StatTile`'s fourth accent,
  `CoverGradient`'s ramp) using Tailwind v4's `var()`-shorthand (`duration-(--dur-ui)`,
  `ease-(--ease-brand)`) or bracket arbitrary values with an explicit fallback
  (`text-[var(--brand-4,var(--brand-3))]`) where an undefined var would otherwise invalidate the
  whole declaration. None of these are redefined in `globals.css` — that stays F1's file.
- **No `ui/form.tsx`.** See the dedicated section above.
