## What I built

- `motion@13.3.0` (`motion/react` + `motion/react-m`). Its peer range is `react ^18 || ^19`, and it runs on React 19.2.8 with no warnings.
- `MotionProvider`: `MotionConfig reducedMotion="user"` with the default transition `{ duration: 0.5, ease: [0.22, 1, 0.36, 1] }`, wrapping `LazyMotion strict`. `domAnimation` loads **on demand** (see Decisions).
- `Reveal`, `Stagger` / `StaggerItem`, `HoverLift`, `CountUp`, and the optional extras `ScrollProgress` and `ParallaxLayer`.
- Only `m.*` components are used, only `transform`/`opacity` are animated, every file starts with `'use client'`, and there are no default exports.
- Temporary `/motion-lab/` demo route (`noindex, nofollow`) that shows every primitive. **4.1 deletes `src/app/motion-lab/` before release.**
- 9 Vitest tests in `tests/unit/motion/`, with mocked `IntersectionObserver`, `matchMedia` and layout.

## Usage

All exports come from `@/components/motion`. You can import them into Server Components, since each primitive is its own client boundary.

```tsx
import { CountUp, HoverLift, ParallaxLayer, Reveal, ScrollProgress, Stagger, StaggerItem } from '@/components/motion'

// Reveal: fade + slide up on entering the viewport (once, 20% visible)
<Reveal>…</Reveal>
<Reveal as="section" delay={0.1} y={24} className="…">…</Reveal>

// Stagger: children reveal one after another (default 0.06s apart)
<Stagger as="ul" stagger={0.08} className="grid gap-6 md:grid-cols-3">
  {projects.map((p) => (
    <StaggerItem key={p.slug} as="li">…</StaggerItem>   // StaggerItem also takes y
  ))}
</Stagger>

// HoverLift: -4px lift on hover, 0.98 press on tap, and the same lift on :focus-within
<HoverLift className="rounded-xl border">
  <a href="…">Card with a focusable link</a>
</HoverLift>

// CountUp: final value in the static HTML, counts from 0 when scrolled into view
<CountUp value={35} suffix="%" className="text-4xl tabular-nums" />   // optional duration (s), default 0.7

// Extras
<ScrollProgress className="bg-brand" />         // fixed 2px top bar, aria-hidden, class appended
<ParallaxLayer offset={40}>…decorative…</ParallaxLayer>
```

`StaggerItem` must be a **direct motion child** of a `Stagger` (wrapping it in plain elements is fine; Motion propagates variants through the React tree).

### Recommended defaults per page type

| Where                                                   | Use                                                                                                                                                                | Why                                                                |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| Hero (above the fold)                                   | Plain markup, or `Reveal` if you like. It never animates on load (see hydration strategy). Use `ParallaxLayer offset={24–40}` only for a decorative gradient/blob  | LCP content must stay visible, and an on-load reveal would flicker |
| Section headings                                        | `<Reveal>` with defaults                                                                                                                                           | Subtle, 16px                                                       |
| Lists / grids (projects, experiments, skills, timeline) | `<Stagger as="ul">` + `<StaggerItem as="li">`, `stagger` 0.06–0.1. Use `<Reveal as="li" delay={i * 0.08}>` only for long, independently scrolling lists (timeline) | One observer per group                                             |
| Cards                                                   | `<HoverLift>` around the card, inside the `StaggerItem`                                                                                                            | Keyboard focus gets the same lift                                  |
| Stats / impact strip                                    | `<CountUp value suffix>` inside a `<Reveal>` or `<StaggerItem>`                                                                                                    | The accessible value is always the final one                       |
| Long reading pages (project detail)                     | `<ScrollProgress />` once per page                                                                                                                                 | Decorative, and hidden with reduced motion                         |

Budget reminder (01 §4): reveals stay ≤ 0.7s (the default is 0.5s), and don't stack a `delay` above ~0.3s.

## Hydration strategy (Reveal, Stagger, CountUp)

**Chosen: static HTML first, and arm only below-the-fold elements after hydration.**

1. On the server and during hydration, the primitives render **no motion styles**. A `useSyncExternalStore` hook (`useMotionAllowed`) returns `false` for its server snapshot, so the hydration render matches the server HTML. No-JS users and crawlers see every element at `opacity: 1`, and CountUp shows the final value.
2. After hydration, if motion is allowed (no `prefers-reduced-motion: reduce`, and `MotionConfig reducedMotion` is not `"always"`), a layout effect measures the element **before paint**. It is armed only if `getBoundingClientRect().top >= innerHeight` (entirely below the fold).
3. Armed elements get `animate="hidden"` (0s transition, so it is instant and off screen) and `whileInView="visible"` with `viewport={{ once: true, amount: 0.2 }}`. Elements on screen or above it are never armed, so there is no visible → hidden flicker.

Rejected alternatives:

- `initial="hidden"` + `whileInView`. The SSR HTML then contains `opacity:0`, which leaves content invisible without JS and to some crawlers, and makes above-the-fold content blink.
- A `<noscript>` style override, or an `html.js` class toggled by an inline script. This needs `layout.tsx` edits (owned by 2.1), and above-the-fold content still flickers.
- Remounting with a `key` after mount. It works, but it remounts the whole subtree (lost state, double work).

CountUp follows the same rule. A counter that is already on screen at load keeps showing its final value and does not reset to 0.

## Decisions

- **`domAnimation` loads asynchronously** (`features={() => import('./features').then(m => m.domAnimation)}`) instead of `features={domAnimation}`. With the synchronous import, the provider alone added **+30.2 KB gzip to every page**. That left about 5 KB for the primitives, and a home-like page (Reveal + Stagger + HoverLift + CountUp) measured **≈ +57 KB**. Loading it async is Motion's documented LazyMotion pattern. Nothing is lost, because armed elements are off screen anyway.
- **CountUp loads `animate()` on demand** (`import('./animate-number')`). The fetch starts when a counter is armed, and counting starts once the counter is in view. It still uses `useInView` + Motion's `animate()` as specified. This cut CountUp's first-load cost from about 17 KB to about 1 KB. Digits are written straight to the DOM, so there is no React re-render per frame.
- **`src/components/motion/package.json` → `{ "sideEffects": false }`.** Without it, importing `MotionProvider` through the barrel in `layout.tsx` pulled **every** motion client module into every page (+34 KB). This keeps the barrel tree-shakable for Turbopack.
- **`import * as m from 'motion/react-m'` with static tag maps** (`{ div: m.div, li: m.li }`) instead of `m[as]`, so unused elements tree-shake.
- **No `cn()` in motion components.** tailwind-merge (about 8 KB) would otherwise ship with HoverLift and ScrollProgress. They use a tiny `joinClassNames`, which appends and does not merge, so pass non-conflicting classes.
- **HoverLift keyboard feedback** uses `motion-safe:focus-within:-translate-y-1`. Tailwind 4's `translate-*` sets the standalone `translate` property, which composes with Motion's inline `transform` and so doesn't fight it. Keyboard focus and mouse hover at the same time lift 8px, which is acceptable.
- **CountUp accessibility:** the task asked for an `aria-label` on the wrapper. ARIA 1.2 prohibits `aria-label` on a generic `<span>` (axe `aria-prohibited-attr`), and several screen readers ignore it. The final value is therefore exposed **once** as `sr-only` text, and the animated digits (`[data-count-up]`) are `aria-hidden="true"`. The result is the same, and the markup is valid.
- **Reduced motion:** every primitive checks `useMotionAllowed()` itself, so no inline `transform` is ever written. We don't rely only on `MotionConfig reducedMotion="user"`, which still writes `transform` values. `ScrollProgress` renders nothing, `ParallaxLayer` renders a static wrapper, `HoverLift` has no gestures, and the CSS lift is `motion-safe:` only.
- **Added optional props** (allowed by 02 §4): `StaggerItem.as?: 'div' | 'li'`, `StaggerItem.y?`, `CountUp.duration?`. New exports: `ScrollProgress`, `ParallaxLayer` (+ `*Props`).

## Bundle measurements

Next 16 (Turbopack) no longer prints first-load sizes in `next build`. I measured by summing `gzip -9` of every `/_next/static/chunks/*.js` referenced by each exported route's HTML (script tags plus the inline RSC payload).

| Route                                                                                    | Before (`origin/next`, no motion) | After    | Added                      |
| ---------------------------------------------------------------------------------------- | --------------------------------- | -------- | -------------------------- |
| `/`, `/bio/`, `/experiments/`, `/projects/`, `/projects/sample-project/` (provider only) | 172.3 KB                          | 185.0 KB | **+12.7 KB** ✅            |
| `/motion-lab/` (every primitive, including ScrollProgress and ParallaxLayer)             | n/a                               | 201.4 KB | **+29.1 KB** ✅ (vs 172.3) |

Lazy chunks, not part of first load and fetched after hydration: `domAnimation` features **17.3 KB**, and `animate()` for CountUp **10.1 KB** (only when a counter is armed).

Intermediate measurements that drove the decisions: sync `domAnimation` + barrel without `sideEffects` → +57.3 KB on every page. Adding `sideEffects: false` → +30.2 KB. With all primitives on one page (sync) → +63 KB.

```ts
import { expect, type Page, test } from '@playwright/test'

const ROUTE = '/motion-lab/'

async function scrollThrough(page: Page) {
  const height = await page.evaluate(() => document.documentElement.scrollHeight)
  const step = 250
  for (let y = 0; y <= height; y += step) {
    await page.evaluate((top) => window.scrollTo(0, top), y)
    await page.waitForTimeout(40)
  }
  await page.evaluate(() => window.scrollTo(0, document.documentElement.scrollHeight))
  await page.waitForTimeout(1200)
}

/** Elements with their own non-empty text, and their effective opacity (product over ancestors). */
function textOpacities(page: Page) {
  return page.evaluate(() => {
    const out: { text: string; opacity: number; visibility: string }[] = []
    for (const el of Array.from(document.body.querySelectorAll('*'))) {
      if (['SCRIPT', 'STYLE', 'NOSCRIPT', 'TEMPLATE'].includes(el.tagName)) continue
      if (el.closest('.sr-only')) continue
      const ownText = Array.from(el.childNodes)
        .filter((n) => n.nodeType === Node.TEXT_NODE)
        .map((n) => n.textContent ?? '')
        .join('')
        .trim()
      if (!ownText) continue
      let opacity = 1
      for (let node: Element | null = el; node; node = node.parentElement) {
        opacity *= Number(getComputedStyle(node).opacity)
      }
      out.push({ text: ownText.slice(0, 40), opacity, visibility: getComputedStyle(el).visibility })
    }
    return out
  })
}

test.describe('reduced motion', () => {
  test.use({ reducedMotion: 'reduce' })

  test('no inline transform anywhere after scrolling, all text visible', async ({ page }) => {
    const errors: string[] = []
    page.on('console', (msg) => msg.type() === 'error' && errors.push(msg.text()))
    await page.goto(ROUTE, { waitUntil: 'networkidle' })
    await scrollThrough(page)
    // Hover a lift card too: reduced motion must not add a transform.
    await page.getByRole('heading', { name: 'Card one' }).hover()
    await page.waitForTimeout(400)
    const transformed = await page.evaluate(() =>
      Array.from(document.querySelectorAll<HTMLElement>('*'))
        .filter((el) => el.style && el.style.transform !== '')
        .map((el) => `${el.tagName}.${el.className}: ${el.style.transform}`),
    )
    expect(transformed).toEqual([])
    const hidden = (await textOpacities(page)).filter((t) => t.opacity !== 1)
    expect(hidden).toEqual([])
    expect(errors).toEqual([])
  })
})

test.describe('javascript disabled', () => {
  test.use({ javaScriptEnabled: false })

  test('every text is visible (opacity 1)', async ({ page }) => {
    await page.goto(ROUTE)
    await scrollThrough(page)
    const texts = await textOpacities(page)
    expect(texts.length).toBeGreaterThan(20)
    expect(texts.filter((t) => t.opacity !== 1 || t.visibility !== 'visible')).toEqual([])
    // CountUp renders its final value in the static HTML.
    await expect(page.locator('dd').first()).toContainText('35%')
    await expect(page.locator('dd').last()).toContainText('2.5x')
  })
})

test.describe('motion enabled', () => {
  test('no visible element is hidden at hydration; reveals, counters and lift work', async ({
    page,
  }) => {
    const errors: string[] = []
    page.on('console', (msg) => msg.type() === 'error' && errors.push(msg.text()))
    page.on('pageerror', (err) => errors.push(err.message))
    // Record any element that gets opacity 0 while it intersects the viewport (a flicker).
    await page.addInitScript(() => {
      const w = window as unknown as { __flicker: string[]; __recording: boolean }
      w.__flicker = []
      w.__recording = true
      new MutationObserver((records) => {
        for (const r of records) {
          const el = r.target as HTMLElement
          if (!w.__recording || el.style?.opacity !== '0') continue
          const rect = el.getBoundingClientRect()
          if (rect.bottom > 0 && rect.top < window.innerHeight) {
            w.__flicker.push(`${el.tagName} ${el.textContent?.slice(0, 30)}`)
          }
        }
      }).observe(document, { attributes: true, attributeFilter: ['style'], subtree: true })
    })
    await page.goto(ROUTE, { waitUntil: 'networkidle' })
    await page.waitForTimeout(1500)
    // Hydration + lazy feature loading are done: stop recording before scrolling starts reveals.
    await page.evaluate(() => ((window as unknown as { __recording: boolean }).__recording = false))
    expect(
      await page.evaluate(() => (window as unknown as { __flicker: string[] }).__flicker),
    ).toEqual([])

    const aboveFold = page.getByText('This reveal is on screen at load').locator('..')
    await expect(aboveFold).not.toHaveAttribute('style', /opacity/)

    // Below-the-fold reveal is armed (hidden) before it is scrolled into view.
    const belowFold = page.getByText('Default reveal: 16px, no delay.').locator('..')
    await expect(belowFold).toHaveCSS('opacity', '0')
    const counter = page.locator('[data-count-up]').first()
    await expect(counter).toHaveText('0%')
    await expect(page.getByText('Alpha', { exact: true })).toHaveCSS('opacity', '0')

    await scrollThrough(page)
    await expect(belowFold).toHaveCSS('opacity', '1')
    for (const item of ['Alpha', 'Foxtrot']) {
      await expect(page.getByText(item, { exact: true })).toHaveCSS('opacity', '1')
    }

    await counter.scrollIntoViewIfNeeded()
    await expect(counter).toHaveText('35%', { timeout: 3000 })
    await expect(page.locator('[data-count-up]').last()).toHaveText('2.5x')

    const card = page.getByRole('heading', { name: 'Card one' }).locator('..')
    await card.hover()
    await expect
      .poll(() => card.evaluate((el) => (el as HTMLElement).style.transform))
      .toContain('translateY(-4px)')

    // Keyboard focus inside HoverLift lifts it through CSS (`translate`, not `transform`).
    await page.mouse.move(0, 0)
    await card.getByRole('link').focus()
    await expect(card).toHaveCSS('translate', '0px -4px')

    // Parallax and scroll progress are active.
    const parallax = page.getByText('Parallax layer (±60px)').locator('..')
    await parallax.scrollIntoViewIfNeeded()
    await expect
      .poll(() => parallax.evaluate((el) => (el as HTMLElement).style.transform))
      .toContain('translateY')
    await expect(page.locator('div[aria-hidden="true"].fixed')).toHaveCount(1)

    const hidden = (await textOpacities(page)).filter((t) => t.opacity !== 1)
    expect(hidden).toEqual([])
    expect(errors).toEqual([])
  })
})
```

## Notes for downstream agents

- **2.1 (`layout.tsx`):** `MotionProvider` is already wired in, so keep it wrapping `<main>`. Importing it from `@/components/motion` is fine (the `sideEffects` flag keeps the barrel tree-shakable). If you add `ScrollProgress` globally, give it a brand colour class (`bg-brand` after 1.1).
- **2.2–2.5:** wrap content, don't write animation code. Don't pass conflicting Tailwind classes to `HoverLift` / `ScrollProgress` (`className` is appended, not merged). `Reveal`, `Stagger` and `HoverLift` render a wrapper element, so put layout classes (`grid`, `gap`) on them directly.
- **`motion.*` is forbidden** inside `MotionProvider` (`LazyMotion strict` throws). Use `import * as m from 'motion/react-m'` if you really need a custom motion element, and gate it with `useMotionAllowed` from `@/components/motion/shared` for reduced motion.
- **2.2 (impact strip):** `<CountUp value={a.metric.value} suffix={a.metric.unit} />`. On a tall desktop viewport the strip may already be on screen at load; it then shows the final number without counting, by design.
- **3.2:** adopt the e2e spec above (point `ROUTE` at a real page once 4.1 removes `/motion-lab/`) and add the `/motion-lab/` checks to axe if you run it before 4.1.
- **4.1:** delete `src/app/motion-lab/`. Nothing else references it.
