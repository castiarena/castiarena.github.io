## Mission
Put the delivery pipeline from `03-deployment-flow.md` into code: CI on every PR, Vercel previews configured from the repo, a production deploy workflow to GitHub Pages (added now, but it only runs on `main`), an export verification script, and a deployment runbook.

`docs/plan/00-README.md`, **`docs/plan/03-deployment-flow.md` (the whole file)**, `02-shared-contracts.md` (§5), `04-agent-loop-protocol.md`, `docs/handoffs/0.1.md`, `docs/DEPLOYMENT-legacy.md`

## You own
`.github/**`, `vercel.json`, `scripts/**`, `docs/DEPLOYMENT.md`, `docs/handoffs/1.4.md`, and **adding** scripts to `package.json` (don't change existing ones).

## Tasks
1. **Look up the current major version** of each action used in 03 §4 (`actions/checkout`, `actions/setup-node`, `pnpm/action-setup`, `actions/upload-artifact`, `actions/download-artifact`, `actions/upload-pages-artifact`, `actions/deploy-pages`) on their GitHub release pages, and pin to that major. Record the versions in the handoff.
2. **`.github/workflows/ci.yml`**: implement 03 §4 `ci.yml`. Add a `format:check` step after lint.
3. **`.github/workflows/deploy-pages.yml`**: implement 03 §4, including the `workflow_dispatch` `ref` input for rollback.
4. **`scripts/verify-export.mjs`**: pure Node, no deps. Checks the list in 03 §4. It reads project slugs by parsing `out/projects/*/index.html` folders and compares their count to the number of `slug:` entries in `src/content/projects.ts` (a regex count is fine). `sitemap.xml`/`robots.txt` absence is a **warning** unless `VERIFY_STRICT=1` (3.1 turns strict on). It also fails if any `.html` contains `href="/castiarena.github.io/` or `src="/castiarena.github.io/` (a basePath leak). Exit code 1 on failure, with a readable report.
5. **`vercel.json`**: exactly as in 03 §4.
6. **`.github/pull_request_template.md`**: summary, handoff link, preview link, screenshots, and a checklist (gate passed, no new `use server`, a11y checked, reduced motion checked).
7. **`.github/dependabot.yml`**: weekly npm (group minor/patch) + weekly github-actions, target branch `next`.
8. **`.github/CODEOWNERS`**: `* @castiarena`.
9. **`docs/DEPLOYMENT.md`**: an operator runbook covering platform roles, the branch model, the one-time setup checklist (03 §5), cutover (03 §6), rollback (03 §7) including the legacy Pages source from `DEPLOYMENT-legacy.md`, and the gotchas (03 §8).
10. **Validation**:
    - Lint the workflows with `actionlint` (`pnpm dlx actionlint` isn't available, so use the Docker image `rhysd/actionlint` or download the binary).
    - Run `ci.yml` locally with `act` if Docker is available (`act pull_request -j verify`). Otherwise rely on the real PR run.
    - Parse `vercel.json` against its schema (fetch `https://openapi.vercel.sh/vercel.json` and validate with `ajv-cli` via `pnpm dlx`).
11. **Do not** change repo settings, Pages settings or Vercel project settings. Those are for the human (03 §5). List them in the handoff as **Needs human input**, with direct links to the settings pages.

## Acceptance criteria
- [ ] Standard gate passes, and `node scripts/verify-export.mjs` passes on a fresh `pnpm build`
- [ ] `actionlint` reports 0 errors
- [ ] `vercel.json` validates against the schema
- [ ] On your PR, `ci / verify` and `ci / e2e` run and pass, and the Vercel preview is created
- [ ] `deploy-pages.yml` does **not** run on your PR (trigger is `main` + dispatch only)
- [ ] A deliberately broken export (temporarily delete `out/bio/index.html`) makes `verify-export` exit 1. Show this in the handoff and do not commit the break
