## Mission
Replace the seed content with real, typed data from the CV and the inputs you have, and add a runtime validator so bad content fails the build instead of shipping broken.

## Context to load first
`docs/plan/00-README.md`, `01-architecture.md` (§5 Privacy/Content), `02-shared-contracts.md` (§1, §2, §5), `04-agent-loop-protocol.md`, **`docs/plan/assets/cv-content.md`**, `docs/plan/05-inputs-needed.md`, `docs/handoffs/0.1.md`

## You own
`src/content/profile.ts`, `experience.ts`, `skills.ts`, `experiments.ts`, `projects.ts`, `src/content/schema.ts` (new), `src/lib/format.ts`, `tests/unit/content/**`, `docs/handoffs/1.2.md`. You may improve the **bodies** of helpers in `src/content/index.ts`, but not their signatures. `types.ts` is frozen (use a CCR).

## Tasks
1. **`profile.ts`**: from `cv-content.md`. `role: 'Senior Frontend Engineer'`, `yearsOfExperience: 10`, `location: 'Trevelin, Patagonia, Argentina'`, `avatar.src: '/images/profile.jpg'` with a descriptive alt, `cvHref: '/cv/agustin-castiarena-resume.pdf'`, socials for LinkedIn, GitHub (`https://github.com/castiarena`) and Email (`mailto:castiarena@gmail.com`). Tagline default from 05. **No phone number anywhere.**
2. **`experience.ts`**: all 4 roles verbatim, newest first, ids `riverside`, `realworld-one`, `westwing`, `mercado-libre`. Dates as `YYYY-MM`. Add `companyUrl` for the public company sites. Infer `stack` only when the CV text says it (e.g. GraphQL for Riverside, micro frontends for Westwing); otherwise leave it out.
3. **`skills.ts`**: `achievements` (4, with `metric.value` numbers and unit `%`), `skillGroups` (3 groups in the CV order), `courses` (2, provider "Frontend Masters", `href` to the course page on frontendmasters.com only if you can confirm the URL; otherwise leave it out).
4. **`experiments.ts`**: use real entries from `05-inputs-needed.md` if you have them. Otherwise add **3 clearly marked placeholders** (`title: 'TODO(agustin): Experiment title'`, `href: 'https://castiarena.github.io/'`), with `image` left out. Include one real entry for the legacy site: `{ slug: 'portfolio-v1', title: 'Portfolio v1', description: 'Previous portfolio built with Vite and TypeScript.', href: 'https://github.com/castiarena/castiarena.github.io/tree/legacy-v1', tags: ['Vite','TypeScript'], year: <year of legacy last commit> }`.
5. **`projects.ts`**: real entries from 05 if you have them. Otherwise **3 placeholder case studies**, clearly marked TODO, derived from CV themes, *without inventing facts, numbers or confidential details*:
   - `recording-studio-architecture`: modular GraphQL microservices (Riverside)
   - `vr-ar-healthcare-platform`: team lead, client-facing platform (Realworld One)
   - `micro-frontend-migration`: shared UI kit + checkout migration (Westwing)
   Set `cover.src` to `/images/projects/<slug>.svg` (2.5 creates placeholders), `featured: true` for all 3, `order` 1–3, and empty `links`. Every sentence not taken from the CV starts with `TODO(agustin):`.
6. **`schema.ts`**: zod schemas that mirror `types.ts` (use `satisfies z.ZodType<Profile>` etc. so they stay in sync), with rules: unique slugs/ids, `description ≤ 140`, `summary ≤ 200`, valid URLs, `start ≤ end`, image paths starting with `/images/`. Export `validateContent()`.
7. Call `validateContent()` at module load in `src/content/index.ts` **only when `process.env.NODE_ENV !== 'test'`**, so `next build` fails on invalid content. This is a body change, and the signatures stay the same.
8. **`src/lib/format.ts`**: `formatMonth('2023-02') → 'Feb 2023'`, `formatRange(start, end) → 'Feb 2023 — Jul 2026'` (and `'Present'`), `durationLabel(start,end) → '3 yrs 5 mos'`. Use `Intl.DateTimeFormat('en', { month:'short', year:'numeric', timeZone:'UTC' })`.
9. Tests: schema accepts the real content and rejects crafted bad fixtures (duplicate slug, overlong description, end before start), plus format function tests and a **privacy test** that fails if any content file matches a phone pattern (`/\+?\d[\d\s-]{8,}\d/`) or the string `311739`.

## Acceptance criteria
- [ ] Standard gate passes, and `pnpm build` creates `out/projects/<slug>/index.html` for every project
- [ ] `validateContent()` passes on real data, and each bad fixture fails with a readable message
- [ ] The privacy test passes
- [ ] Every CV bullet in `cv-content.md` appears verbatim in `experience.ts` (a test that compares them)
- [ ] Every placeholder is marked `TODO(agustin)` and listed in the handoff under **Needs human input**
