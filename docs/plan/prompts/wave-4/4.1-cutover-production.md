# Agent 4.1 — Release & Production Cutover (human in the loop)

| Wave | Mode | Depends on | Unblocks |
|---|---|---|---|
| 4 | **Sequential, with human approvals** | All Wave 3 merged, 3.3 verdict **GO** | 4.2 |

## Mission
Ship v2.0.0 to `https://castiarena.github.io`, replacing the Vite site, with a safe and reversible cutover. You prepare everything and run the checks. **The human does the irreversible clicks** (Pages source switch and merge to `main`), and you pause for them.

## Context to load first
`docs/plan/00-README.md`, **`docs/plan/03-deployment-flow.md` §5–§7**, `04-agent-loop-protocol.md`, `docs/DEPLOYMENT.md`, `docs/DEPLOYMENT-legacy.md`, **`docs/PRE-CUTOVER-REPORT.md`**, all handoffs (collect every open **Needs human input** and **CCR**)

## You own
Branch `release/v2.0.0`, deleting the temporary routes (`src/app/styleguide/**`, `src/app/motion-lab/**`) and their tests, `README.md`, `CHANGELOG.md`, `docs/handoffs/4.1.md`, `docs/RELEASE-v2.0.0.md`.

## Phase A: release preparation (autonomous)
1. `git switch -c release/v2.0.0 origin/next`.
2. **Gate check**: if `PRE-CUTOVER-REPORT.md` isn't **GO**, stop with BLOCKED and list the blockers.
3. **Release blockers scan**: fail if any of these is true.
   - `grep -rn "TODO(agustin)" src/content` finds anything. **Stop and ask the human** to provide the content (link `05-inputs-needed.md`), or to approve hiding the unfinished entries. If hiding is approved, add `draft: true` handling only through a CCR already accepted, or remove the entries from content.
   - Placeholder project covers are still in use (ask the human whether that's acceptable for launch).
   - Findings from 3.2 marked severity high are still open.
4. Remove the temporary routes `styleguide` and `motion-lab` and any references to them in robots/sitemap.
5. Refresh `README.md` (what it is, stack, local dev, deploy summary with a link to `docs/DEPLOYMENT.md`) and write `CHANGELOG.md` `## 2.0.0` from the handoffs.
6. Run the full gate: standard gate + `VERIFY_STRICT=1 node scripts/verify-export.mjs` + `pnpm e2e` + `pnpm lhci autorun`. Everything must pass.
7. Open PR `release/v2.0.0 → next` and wait for green + Vercel preview, then merge after the human approves (step 8).
8. Open PR **`next → main`** titled `release: v2.0.0`, with a body that includes the PRE-CUTOVER summary, the Lighthouse scores, the Vercel staging link, the rollback commands, and a checkbox list for the human steps below.

## Phase B: human checkpoint (pause)
Print this block, then **wait** for the human to confirm each line (poll PR comments for `/approve-cutover`, or stop and resume when re-invoked):

```
HUMAN ACTION REQUIRED — cutover v2.0.0
[ ] 1. Review staging: <vercel next URL>
[ ] 2. Confirm legacy-v1 tag/branch == pre-merge main tip (agent verified: <sha>)
[ ] 3. Settings → Pages → Source: GitHub Actions   (https://github.com/castiarena/castiarena.github.io/settings/pages)
[ ] 4. Merge PR "release: v2.0.0" into main
Comment /approve-cutover on the PR when 3 and 4 are done.
```

## Phase C: deploy watch (autonomous)
9. Watch the `deploy-pages` run for the merge commit (`gh run watch`). If it fails: collect logs, and **don't retry more than once**. Then write the rollback recommendation (03 §7) and stop with BLOCKED.
10. Once it's green, poll `https://castiarena.github.io/` until the HTML contains the new build ID (`/_next/static/<buildId>/`), which can take a few minutes because of the CDN cache. Timeout: 15 min.
11. `git tag v2.0.0 origin/main && git push origin v2.0.0`, and create a GitHub Release with the changelog.
12. Write `docs/RELEASE-v2.0.0.md`: timestamps, run links, commit SHAs, before/after screenshots (before from 3.3), and the exact rollback commands for this release.

## Acceptance criteria
- [ ] The release PR is merged into `main` by the human, and the `deploy-pages` run is green
- [ ] `https://castiarena.github.io/` serves the new build (build ID check)
- [ ] Temporary routes are gone: `/styleguide/` and `/motion-lab/` return 404
- [ ] Tag `v2.0.0` and a GitHub Release exist
- [ ] `docs/RELEASE-v2.0.0.md` is committed (via a follow-up PR to `next`, then fast-forward `main` in the next release, or directly in the release PR before merge)

## Loop rules
Follow `docs/plan/04-agent-loop-protocol.md`. The pause in Phase B is **not** a failed iteration. Final line:
`AGENT_RESULT id=4.1 status=<DONE|BLOCKED|WAITING_HUMAN> pr=<url> deploy_run=<url> ccr=0`
