# Agent 3.3 — Deployment Dry-Run & Pre-Cutover Audit

| Wave | Mode | Depends on | Unblocks |
|---|---|---|---|
| 3 | Parallel with 3.1, 3.2 | UI phase + V1 merged, 1.4 | 4.1 |

## Mission
Prove that the production pipeline works **before** touching `main` or the live site. Deploy the exact artifact to a throwaway GitHub Pages site, check Vercel staging, look for route collisions with other Pages sites on the account, and produce a go/no-go report.

## Context to load first
`docs/plan/00-README.md`, **`docs/plan/03-deployment-flow.md`**, `04-agent-loop-protocol.md`, `docs/DEPLOYMENT.md`, `docs/DEPLOYMENT-legacy.md`, handoffs `1.4`

## You own
`docs/handoffs/3.3.md`, `docs/PRE-CUTOVER-REPORT.md`, and fixes inside `.github/**`, `vercel.json`, `scripts/**` **only** for defects found by the dry-run (record each fix in the report). You may create a **temporary sandbox repo** under the account (see task 2) and must delete it or leave a documented instruction to delete it.

## Tasks
1. **Vercel staging check**: find the `next` branch deployment URL (`gh api repos/castiarena/castiarena.github.io/deployments?ref=next` or the Vercel bot comment). With Playwright, visit all routes, confirm 200s, no console errors, and `x-robots-tag: noindex` on preview responses. Confirm that `main` has **no** Vercel production deployment configured to build (vercel.json `deploymentEnabled`).
2. **GitHub Pages dry-run** (a project site, so it needs a basePath; this tests the pipeline, not the paths)
   - Preferred: ask the human in the handoff for permission if the environment cannot create repos. If allowed, `gh repo create castiarena/portfolio-v2-dryrun --private=false`.
   - Push the `out/` artifact built with `NEXT_PUBLIC_SITE_URL=https://castiarena.github.io`, **plus** a variant built with a temporary `BASE_PATH=/portfolio-v2-dryrun` env hook applied **only on the dry-run branch copy** (do not merge that hook), deployed by a copy of `deploy-pages.yml`.
   - Check that the workflow permissions (`pages: write`, `id-token: write`), the `github-pages` environment and the artifact upload/deploy steps all succeed, and that the deployed site serves `/`, nested `index.html` routes, `404.html` and `_next/static/*` (proves `.nojekyll`/underscore handling).
   - Record run URLs and timings, then delete the sandbox repo (or leave the exact `gh repo delete` command for the human).
   - If creating a repo isn't possible: run `deploy-pages.yml`'s build job locally with `act` and validate the artifact tarball structure instead. Mark this as partial in the report.
3. **Route collision audit**: `gh api users/castiarena/repos --paginate -q '.[] | select(.has_pages) | .name'`. For every repo with Pages enabled, check whether its name matches a top-level route or folder in `out/` (`bio`, `projects`, `experiments`, `cv`, `images`, `og`, `_next`, …). Report collisions with a recommendation (rename the route or disable that repo's Pages). List the non-colliding ones as **candidate Experiments** with their URLs.
4. **Current production snapshot**: record the current `https://castiarena.github.io` response (status, title, a full-page screenshot) for before/after comparison, plus the current Pages settings via `gh api repos/castiarena/castiarena.github.io/pages`.
5. **Settings audit** (read-only, via `gh api`): branch protection on `main`/`next`, required checks names match the actual check names from 1.4, and the `github-pages` environment has branch policy `main`. List gaps as **Needs human input**.
6. **Content readiness**: `grep -rn "TODO(agustin)" src/content` count, plus a list of placeholder images still in use.
7. Write **`docs/PRE-CUTOVER-REPORT.md`**: a Go/No-Go table (Pipeline ✅/❌, Vercel staging, Collisions, Settings, Content readiness, Quality gate from 3.2 status, SEO from 3.1 status), evidence links, and blockers with owners.

## Acceptance criteria
- [ ] The dry-run Pages deployment succeeded, with the URL and run link recorded (or documented partial fallback)
- [ ] The collision audit table is complete
- [ ] `PRE-CUTOVER-REPORT.md` has an explicit **GO** or **NO-GO** with reasons
- [ ] No changes were made to the production repo's settings, Pages source or `main`
- [ ] The sandbox repo is deleted or a deletion command is left for the human
