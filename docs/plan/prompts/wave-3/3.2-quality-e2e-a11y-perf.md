## Mission
Lock in quality with automated checks that run on every PR: cross-page E2E journeys, axe accessibility scans, reduced-motion and no-JS checks, visual smoke snapshots, and Lighthouse CI budgets.

## Context to load first
`docs/plan/00-README.md`, `01-architecture.md` (§4 motion budget, §5), `04-agent-loop-protocol.md`, **all Wave 2 handoffs** (they list the behaviours to test)

## You own
`tests/e2e/**`, `playwright.config.ts` (project additions only), `lighthouserc.json`, `.github/workflows/lighthouse.yml` (new file; coordinate names with 1.4's conventions), `docs/handoffs/3.2.md`, and adding `@lhci/cli` to devDeps plus `"lhci"` script.

## Tasks
1. **E2E journeys** (`tests/e2e/journeys/*.spec.ts`) against the built `out/`:
   - *Recruiter path*: `/` → hero CTA "Read bio" → timeline has 4 roles → Download CV returns a PDF (`response.headers()['content-type']`).
   - *Hiring manager path*: `/` → featured project card → detail → next project → "All projects".
   - *Explorer path*: `/experiments/` → toggle a tag → URL updates → reload keeps the filter → open an external link (assert `target=_blank`, don't navigate away).
   - *Contact path*: header Contact → invalid submit → valid submit with `page.route` mock → success.
   - *Navigation*: every `siteConfig.nav` link from every page; the mobile sheet at 375px; 404 for `/does-not-exist/`.
   - *Theme*: toggle to light, reload, still light; no hydration warnings in console on any route (`page.on('console')` fails on `error` and on messages containing "Hydration").
2. **Accessibility** (`tests/e2e/a11y.spec.ts`): `@axe-core/playwright` on every route (including one project detail and the open contact dialog and mobile sheet) in light and dark. Fail on `serious`/`critical`. Keyboard-only traversal test for header → main → footer.
3. **Reduced motion & no-JS** (`tests/e2e/resilience.spec.ts`)
   - Context `reducedMotion: 'reduce'`: after scrolling through each page, no element has a non-identity inline `transform` from Motion.
   - Context `javaScriptEnabled: false`: all headings and body text visible (opacity 1), nav links work, and Bio timeline complete.
4. **Visual smoke** (`tests/e2e/visual.spec.ts`): `toHaveScreenshot` for `/`, `/bio/`, `/projects/`, `/experiments/` at 375/1280 in dark theme, with animations disabled and `maxDiffPixelRatio: 0.02`. Commit baselines generated **in the Playwright Linux docker image** (`mcr.microsoft.com/playwright:<version>-noble`) so CI matches.
5. **Lighthouse CI**: `lighthouserc.json` with `staticDistDir: "./out"`, URLs `/`, `/bio/`, `/projects/`, `/experiments/`, first project detail, 3 runs, mobile preset. Assertions: `categories:performance ≥ 0.9`, `accessibility ≥ 0.95`, `best-practices ≥ 0.95`, `seo ≥ 0.95`, `largest-contentful-paint ≤ 2500`, `cumulative-layout-shift ≤ 0.05`, `total-blocking-time ≤ 200`. Workflow `lighthouse.yml` runs on PRs to `next`/`main` after build, uploading reports as artifacts (temporary public storage off).
6. **Fix nothing in product code.** If a check fails because of a product bug, record a finding in the handoff (route, issue, owner agent id, suggested fix) and mark the test `test.fixme` with a link to the finding, **only** if the gate would otherwise block all of Wave 3. Otherwise leave it failing and report BLOCKED.

## Acceptance criteria
- [ ] Standard gate passes
- [ ] `pnpm e2e` passes locally and in CI (or failures are fully documented findings as above)
- [ ] `pnpm lhci autorun` passes all assertions on the current `next`
- [ ] Total E2E runtime in CI ≤ 6 minutes (use sharding if needed)
- [ ] Handoff has a **Findings** table: id · route · severity · owner · fix suggestion
