## Mission
Give visitors a low-friction way to reach Agustin from any page. **No server is available** (GitHub Pages), so the form posts to a third-party form endpoint configured by env var and falls back gracefully to `mailto:`.

## Tasks
1. **`ContactDialog({ trigger? })`** (`'use client'`): shadcn `Dialog`, where the default trigger is a `Button` "Contact". Title "Get in touch", description "I usually reply within a couple of days."
2. **`ContactForm`**: shadcn `Form` + `react-hook-form` + zod.
   - Fields: name (2–80), email (valid), message (20–2000, char counter), plus a **honeypot** hidden field `company` (reject if filled) and a minimum time-to-submit of 3s (anti-bot).
   - Submit: if `process.env.NEXT_PUBLIC_FORM_ENDPOINT` is set, `fetch(endpoint, { method: 'POST', headers: { Accept: 'application/json', 'Content-Type': 'application/json' }, body })`. This works with Formspree and Web3Forms JSON APIs; document both payload shapes and support both via a small adapter keyed on the endpoint host.
   - States: idle, submitting (button spinner, fields disabled), success (sonner toast + dialog content swaps to a thank-you with a Close button), error (inline alert + "Email me instead" `mailto:` link that pre-fills subject/body from the form values).
   - **If no endpoint is configured**, the submit button label becomes "Open email app" and it builds a `mailto:` URL (encode it properly) instead of fetching.
3. **`ContactCTA({ className? })`**: a primary button that opens `ContactDialog`, plus a secondary copy-email icon button (Clipboard API with a fallback, toast "Email copied").
4. Accessibility: labels tied to inputs, errors via `aria-describedby`, focus goes to the first invalid field on submit, the dialog returns focus to the trigger, and the success message is announced (`role="status"`).
5. Privacy: the email appears only in `mailto:`/copy actions, not as visible body text on every page (it's fine inside the dialog).
6. Document the env var in the handoff for the human and for 1.4's runbook: `NEXT_PUBLIC_FORM_ENDPOINT` in GitHub repo **Variables** and Vercel **Preview** env.
7. Tests (mock `fetch`): validation messages; honeypot blocks; too-fast submit blocks; success path; error path shows mailto fallback; no-endpoint path builds a correctly encoded mailto URL.
